3 Complete Flow - Start to End

1

User Opens Speed Test

User visits https://speed.spectra.co in their browser. The frontend loads from Gurgaon main server with Spectra branding and server selection dropdown.

2

User Selects Test Server

User picks a server from dropdown (Gurgaon, Bangalore, Mumbai, or Chennai). JavaScript dynamically switches test endpoints to the selected server.

3

Speed Test Execution

When user clicks "Start", tests run in sequence:

  • Ping/Jitter Test - 10 samples for RTT measurement
  • Download Test - Progressive download (10-30 seconds)
  • Upload Test - Progressive upload (10-30 seconds)
4

Custom Measurements

After LibreSpeed completes:

  • Packet Loss - 20 ping requests, count failures, calculate %
  • Latency - Median value from 20 samples (eliminates outliers)
5

Results Saved to Database

All results sent to Gurgaon MySQL (regardless of test server):

  • Download/Upload (Mbps), Ping/Jitter (ms)
  • Packet Loss (%), Latency (ms)
  • Test Server name, Client IP, Timestamp
  • api_fetch_status set to 'pending'
6

SOAP API Enrichment (Cron Job)

Daily cron job at 11:50 AM:

  • Fetches records where api_fetch_status = 'pending'
  • Calls SOAP API with client IP
  • Updates record with customer info (name, plan, address, city)
  • Sets status: 'completed' | 'not_found' | 'error'

⚠️ Important: Private IP Requirement

The SOAP API only returns data for private IPs (10.x.x.x, 172.16.x.x, 192.168.x.x).

Users on public IPs (not on Spectra's network) will be marked as 'not_found'. This is expected behavior.

7

View Analytics

Admins access https://speed.spectra.co/results/stats.php for summary statistics, filterable data table, and CSV export.

5 SOAP API Integration

API Endpoint

WSDL: https://unify.spectra.co/unifyejb/UnifyWS?wsdl Method: getDetailsByIp

⚠️ CRITICAL: Private IP Requirement

The SOAP API ONLY works with PRIVATE IP addresses!

✅ Works: 10.x.x.x, 172.16.x.x, 192.168.x.x

❌ No Data: Public IPs (like 203.x.x.x, 49.x.x.x)

The Unify system only tracks IPs assigned within Spectra's internal network. Users running speedtest from public internet will return empty results.

6 Custom Measurements

Packet Loss

Standard LibreSpeed doesn't measure packet loss. We added custom measurement:

StepAction
1Send 20 ping requests to selected server
2Count how many requests fail or timeout
3Calculate: (failed ÷ total) × 100 = packet loss %

Latency

LibreSpeed provides "ping" (RTT). We added separate latency using median instead of average:

StepAction
1Collect 20 latency samples during packet loss test
2Sort all samples from lowest to highest
3Take the middle value (median) - eliminates outliers

7 Multi-Server Setup

How It Works

The main frontend at https://speed.spectra.co contains a server dropdown. When user selects a different city:

  • JavaScript changes download/upload/ping endpoints to that city's server
  • Test traffic flows to/from the selected city's server
  • Results are always saved to Gurgaon database via telemetry

Remote Server Requirements

Each remote server (Bangalore, Mumbai, Chennai) needs:

RequirementDetails
✅ RequiredNginx + PHP-FPM installed
✅ RequiredOnly /backend/ folder with 3 files: garbage.php, empty.php, getIP.php
✅ RequiredCORS headers enabled for https://speed.spectra.co
❌ Not neededDatabase
❌ Not neededFrontend files

Why Multi-Server?

Without multi-server: User in Bangalore tests against Gurgaon (~1500km) → High latency, inaccurate speeds

With multi-server: User in Bangalore tests against Bangalore (local) → Accurate "last mile" measurements

9 Troubleshooting

Issue Cause Solution
CORS errors in console Remote server missing CORS headers Add CORS headers to PHP files
API returns empty User has public IP Expected - API needs private IP
Low upload speeds PHP limits too low Increase upload_max_filesize in php.ini
Stats not loading Database connection issue Check telemetry_settings.php
Test shows 0 Mbps Endpoint not responding Check if backend PHP files accessible
Packet loss 0% or 100% Firewall blocking Check server firewall rules
